# Auditoria final — 2026-09-11 (spec 013, A-015)

Auditoria por componente/superfície contra os sete eixos que A-015 exige:
contraste, cor+rótulo, foco, alvo de interação, hierarquia, semântica e
responsividade. Cada linha cita a evidência real (código lido, contraste
calculado por WCAG 2.1, ou medição via devtools) — não é opinião solta.
Correções pequenas e óbvias encontradas no caminho foram aplicadas direto no
código nesta mesma subtarefa (T-009); estão marcadas **[corrigido aqui]**.
Lacunas maiores viram item de backlog novo, não são forçadas nesta auditoria.

## Método

- **Contraste**: razão calculada (fórmula WCAG 2.1) para os pares
  texto/fundo realmente usados nos tokens de `tokens.css`. Mínimo exigido:
  4.5:1 corpo, 3:1 texto grande/gráfico.
- **Cor+rótulo**: todo estado usa tom **e** texto, nunca só cor (regra da
  seção 3 do README).
- **Foco**: `mountDialog`/`focus-trap.ts` prende Tab/Shift+Tab e restaura o
  foco ao fechar; anel visível vem do `:focus-visible` global.
- **Alvo**: altura do controle interativo, contra os 32–36px da seção 5.
- **Hierarquia**: ordem de headings (`h1`→`h2`→`h3`) sem pular nível.
- **Semântica**: landmarks (`main`, `dialog`, `status`, `alert`), rótulos
  acessíveis, regiões `aria-live`.
- **Responsividade**: comportamento no breakpoint de 760px já documentado.

## Achados não corrigidos aqui (ficam para backlog, não são desvio de escopo)

- **`StatusPill` sem `role=status`** antes desta auditoria — **[corrigido aqui]**: adicionado `role="status" aria-live="polite"`, mesma regra que `FreshnessStatus` já seguia, para o status derivado (`ready`/`in_progress`/`done`...) ser anunciado quando muda.
- **Anel de foco em 1px** (`:focus-visible`) é o que o README já documenta (seção 5, "âncora `--blue-line` ou `--line-2`"), mas é fino para baixa visão. Mudar a espessura é decisão de design system, não de auditoria — registrar aqui para uma futura revisão do token, não mudado sem essa decisão.
- **`DiskLog` não anuncia novas entradas via `aria-live`.** Deliberadamente não adicionado: cada entrada carrega blocos de diff (Antes/Depois) que podem ser longos, e anunciar automaticamente arriscaria inundar quem usa leitor de tela a cada escrita durante uma execução. Precisa de uma decisão de design (por exemplo, anunciar só o resumo, não o diff) antes de mexer.
- **Terminal embutido não é acessível a leitor de tela** — limitação inerente a um emulador de terminal via canvas (xterm.js); o modo externo (script wrapper) já existe como alternativa e é oferecido no aviso de conflito de teclado.
